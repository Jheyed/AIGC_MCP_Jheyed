# 质量与验收标准

## 所有工作单元

- 修改符合项目根本要求。
- 没有把核心功能绑定到单一 Agent。
- 没有写入密钥、个人令牌或不可移植的个人绝对路径。
- 相关检查真实执行，失败被如实记录。
- `CHANGELOG.md` 和 `docs/STATUS.md` 已更新。
- 文档没有把计划中的能力描述成已经实现。

## 外部方案选型

- 使用官方来源核实功能和安装方式。
- 记录项目活跃度、版本、许可证和维护风险。
- 说明为何复用、扩展或拒绝该方案。
- 至少包含一个退出或替换路径。
- 区分“文档声称可用”和“本机已经验证”。

## MCP 工具

- 输入输出有明确 schema 和稳定版本。
- 工具面向清晰目标，避免一个工具承担无边界职责。
- 错误可操作，能区分缺模型、缺节点、服务离线、显存不足和输入无效。
- 危险或付费操作需要明确确认。
- 同一核心功能可通过非 Agent 入口测试。
- 至少在两个不同 MCP 客户端上完成基本兼容性验证后，才能宣称“多 Agent 可用”。

## ComfyUI 配方

- 使用 API 格式工作流并通过真实运行验证。
- 记录所需模型、节点、版本与大致显存需求。
- 只开放已定义的可编辑槽位。
- 记录至少一个成功案例和已知失败边界。
- 工作流更新后重新进行最小生成测试。

## 生成记录

- 保存规范化请求、执行计划、seed 和关键参数。
- 保存工作流版本或哈希。
- 保存输入资产和输出文件的可追踪引用。
- 记录失败和重试，不用最终成功覆盖中间问题。
