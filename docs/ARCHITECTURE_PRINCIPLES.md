# 架构原则

本文规定稳定方向，不提前锁死尚未调研完成的具体框架。

## 1. 核心与适配器分离

核心能力至少应能被两种入口调用：

- MCP：供不同 AI Agent 使用；
- CLI 或等价的程序接口：供人工调试、自动测试和无 Agent 环境使用。

Agent 专属配置属于适配器。核心的请求解析、配方选择、运行记录和安全策略不得只存在于适配器中。

## 2. 目标级接口优先

普通 Agent 优先调用目标级能力，例如：

- 检查环境能力；
- 规划生成；
- 使用角色和姿势生成；
- 修改已有结果；
- 解释或复现一次运行；
- 诊断失败。

节点级操作保留为专家能力，不作为默认路径。

## 3. 配方优先于自由构图

一个“配方”由以下内容组成：

- 已验证的 ComfyUI API 工作流；
- 可修改槽位及其类型；
- 所需模型与节点；
- 资源需求；
- 参数安全范围；
- 适用任务与已知限制；
- 验证记录和版本。

Agent 默认选择配方并填写槽位，而不是从零生成节点图。

## 4. 能力发现而非硬编码假设

执行前检查：

- GPU 和显存；
- ComfyUI 版本与运行状态；
- 已安装模型和 custom nodes；
- 工作流兼容性；
- 输入资产存在性；
- 是否涉及网络或费用。

若能力不足，应给出降级选项，不应假装可用。

## 5. 文件是可移交的事实来源

角色包、配方、请求、运行清单、ADR 和状态记录都应保存在普通文件中并可版本控制。聊天记录可以提供背景，但不是项目状态的唯一来源。

## 6. 外部依赖可替换

对官方或社区组件采用薄封装。保存其原生工作流和错误信息，避免把项目锁死在难以迁移的内部格式中。

## 7. 可观察性

每次执行至少产生：

- 规范化请求；
- 已解析的执行计划；
- 实际工作流副本或内容哈希；
- 模型、节点版本和 seed；
- 时间、状态与错误；
- 输入与输出文件清单。

日志不得包含密钥。

## 8. 架构待验证项

以下内容必须通过方案调研或原型验证后再决定：

- 直接扩展官方 `comfy-mcp`，还是在其上建立独立创作层；
- 核心实现语言；
- 请求和角色包的最终 schema；
- 首个本地模型与角色一致性技术；
- 多 Agent 客户端的首批验证组合。
