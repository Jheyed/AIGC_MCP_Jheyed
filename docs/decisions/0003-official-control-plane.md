# ADR-0003：以官方 Comfy MCP 和官方模板作为首选基线

- 状态：Proposed
- 日期：2026-10-18

## 背景

项目需要自然语言驱动本地 ComfyUI，同时要求多 Agent 通用，并优先使用已经发布和验证的相似方案。

## 决策

首个原型拟使用 Comfy Org 官方 `comfy-mcp` / `comfy-cli` 作为底层控制面，使用官方 `workflow_templates` 作为初始配方来源。本项目先只增加目标级 schema、角色资产、配方元数据和运行记录，不 fork 官方 MCP。

## 理由

- 官方 MCP 已覆盖环境查询、工作流验证、运行和输出获取；
- 官方模板有 schema、CI 和兼容性检查；
- 保持上游更新路径，减少重复实现；
- 可以先验证真实缺口，再决定是否开发独立目标级 MCP。

## 后果

- 早期 Agent 仍承担部分自然语言到结构化请求的规划；
- 官方 MCP 为 AGPL-3.0-or-later/商业双许可，必须保持依赖边界和许可证记录；
- beta 版本需要锁定并验证，不应无条件自动升级；
- 如果其接口不能满足目标级编排，本项目后续可能增加独立 MCP 服务。

## 替代方案

- 整套采用 ComfyUI-Agent-Kit：功能丰富，但安装面和第三方依赖范围超出当前 MVP。
- 采用社区大工具面 MCP：灵活，但维护、安全和兼容性验证成本较高。
- 从零实现 ComfyUI 客户端：重复官方能力，暂不合理。

## 验证或复审条件

完成本机最小原型后，将本 ADR改为 `Accepted`、修改方案或新增替代 ADR。至少验证：Windows 启动、硬件识别、模板查询、工作流执行、输出获取和一个非 Codex MCP 客户端的连接可能性。
